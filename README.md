# ZK-SR117: Chunked Zero-Knowledge Attestation of Fair-Lending and Calibration Controls Under SR 11-7

Companion code for the paper:

> M. N. Uddin, A. Anik, E. R. Bhuiyan, and R. T. Orpita, "Privacy-Preserving Supervisory Attestation of Credit Models: Chunked Zero-Knowledge Proofs of Fair-Lending and Calibration Controls Under SR 11-7," submitted to *IEEE Access*, 2026. An earlier version is available as [arXiv:2608.02664](https://arxiv.org/abs/2608.02664).

A bank proves to a supervisor, with zkSNARKs generated by [EZKL](https://github.com/zkonduit/ezkl), that a committed credit model evaluated on an examiner-nonce-sampled batch of real 2022 HMDA mortgage applications satisfies two supervisory controls: the **demographic-parity gap** and the **expected calibration error (ECE)**. The supervisor verifies the proofs without seeing model weights or applicant records. Both controls are attested end-to-end at N = 32,768 applications (K = 32 chunks of n = 1,024), for a five-parameter logistic regression and a 225-parameter multilayer perceptron (`mlp/`).

### Neural-network extension (§VIII-F, Tables VIII–IX)

The `mlp/` folder repeats both controls with a 4–16–8–1 ReLU network (225 parameters) on the same rows, nonce derivations, preprocessing and chunk structure. `mlp/run_all.sh` runs everything in four stages (`install`, `timing`, `full`, `pack`); see `mlp/README.md`. Results of the runs reported in the paper (summaries, per-chunk outputs, binding tests and the precision/chunk-size study) are in `mlp/results/`. These runs used a 64-vCPU AMD EPYC 7742 server with 513 GB RAM; the ECE circuit needs about 41 GB of memory at n = 1,024.

## Data

This repository does not redistribute HMDA microdata. To reproduce:

1. From the FFIEC/CFPB HMDA Data Browser (https://ffiec.cfpb.gov/data-browser/), download the **2022 nationwide Loan Application Register filtered to loan type 1 (conventional)**. The export is named `loan_types_1_year_2022.csv`; place it in the repository root.
2. Run `python3 filter_hmda.py`. It writes `hmda_sample.csv`.

What `filter_hmda.py` does:

- Keeps home-purchase (`loan_purpose = 1`), first-lien (`lien_status = 1`), principal-residence (`occupancy_type = 1`) applications that were originated or denied (`action_taken` ∈ {1, 3}).
- Reads the file in chunks of 500,000 and **stops once at least 600,000 qualifying rows are collected**, so the pool is the first ~600,000 qualifying records in the file's order, not the full national population.
- Converts `debt_to_income_ratio` to numbers: HMDA range codes become their midpoint (e.g., `20%-<30%` → 25), one-sided codes become their bound (e.g., `>60%` → 60), and non-numeric codes such as `Exempt` are dropped. Rows missing income, loan amount, DTI or LTV are dropped.
- Codes the label `action_taken_binary` (1 = originated, 0 = denied).
- Draws a random sample of 500,000 rows (`random_state=11`).

The modelling scripts then keep single-race applicants (`derived_race` ∈ White, Black or African American, Asian, American Indian or Alaska Native, Native Hawaiian or Other Pacific Islander) and code the protected group as nonwhite = 1, White = 0. This leaves **409,905 rows**; the Model A holdout has 102,477. Because the pool depends on the row order of the downloaded file, reproducing these exact counts requires the same 2022 export.

## Installation

```bash
pip install ezkl==23.0.5 onnx onnxruntime pandas scikit-learn numpy
```

Tested with ezkl 23.0.5 and Python 3.12 on Apple Silicon.

**Trusted setup.** The production runs use `ezkl.get_srs()`, which downloads the real Powers-of-Tau ceremony file and needs outbound network access to EZKL's host. `ezkl.gen_srs()` creates a local test-only SRS; do not use it for anything beyond local testing.

## Reproducing the results

```bash
# Data
python3 filter_hmda.py

# Demographic parity (Table V)
python3 06_setup_once_clipped.py
python3 06_driver.py
python3 07_bootstrap_ci_clipped.py
python3 12_version_binding.py

# ECE (Table VII)
python3 13_ece_setup_once.py
python3 13_ece_driver.py
python3 14_ece_bootstrap_ci.py
python3 15_ece_stratified_check.py
python3 16_ece_version_binding.py

# Circuit-design comparison (Table IV)
python3 11_flatsum_real_sweep.py
python3 05_tree_sweep.py
```

The drivers are resumable: rerunning skips chunks that already finished.

## Scope and limitations

This code implements what Table III of the paper lists as implemented end-to-end. Not implemented here: the beacon-derived nonce with an in-circuit sampling proof (§VI-G), a standalone KZG commitment to the model weights (§V-B), and corpus commitment (§VI-C). The tree-reduction compile-time wall is an EZKL-specific finding and has not been tested on other proving backends. Bootstrap intervals use uniform resampling; a stratified recomputation is listed as future work in §X.
